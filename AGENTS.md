# Agents

## Repository map

- `custom_components/powercalc/`: Home Assistant integration
- `profile_library/`: device power profiles
- `utils/measure/`: separate measurement utility project
- `tests/`: integration tests
- `docs/source/`: Zensical documentation

Keep unrelated working-tree changes intact.

## Change-specific rules

### Translations

For any translation key or string change, use
`.agents/skills/powercalc_translations/SKILL.md`.

### Power profiles

For changes under `profile_library/`, use
`.agents/skills/power_profile_pr_reviewer/SKILL.md` when reviewing a PR.

- Do not edit `profile_library/library.json` manually; it is generated by
  `.github/scripts/profile_library/update_library.py`.
- Validate new or changed `model.json` against
  `profile_library/model_schema.json`.
- Keep a model directory to the model ID; put the full product name in
  `aliases` when needed.

### Documentation

Documentation uses Zensical. From `docs/`, validate with:

```sh
uv run --group docs zensical build --clean
```

## Validation

Run checks appropriate to the changed area:

- Integration Python: `uv run pytest tests` and relevant Ruff/type checks.
- Measurement utility: from `utils/measure/`, run its documented tests/checks.
- Profile JSON: run the schema validation/pre-commit checks.
- Before a broad change or PR, run `uv run prek run --all-files` when practical.
- Before making a PR, run the full relevant test suite and ensure it reports
  100% coverage for the changed code.

`pyproject.toml`, `.pre-commit-config.yaml`, and CI workflows are the source of
truth for tool versions and complete validation commands.
